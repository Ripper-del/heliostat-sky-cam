# Pinout і схема підключення (ЛР2)

Плата: NUCLEO-F411RE (MB1136), МК STM32F411RET6, LQFP64, логіка 3.3 В. Файл відповідає `firmware/Platform/Inc/board.h` —
при зміні пінів правити обидва. Значки ⟦…⟧ — значення, які ще треба звірити з первинним документом (номер таблиці/сторінки).

Документи: **DS10314** (datasheet F411), **RM0383** (reference manual), **UM1724** (Nucleo-64), datasheet кожного сенсора.

Живлення: MPU-6050, OV7670, W25Q64, дільники GM5528 — від **3V3** Nucleo; серво SG92R/SG90 — **5 В**, GND спільний з платою.
Піни камери PWDN → GND, RESET → 3V3 (на модулі).

### 1.1. Паралельний інтерфейс камери (запланований, ще не змонтований)

На F411 **немає DCMI** ⇒ захоплення кадру програмне (GPIO). Для 11 ліній (D0–D7, PCLK, HREF, VSYNC) резервуємо порт C: D0–D7 → **PC0–PC7**
(читання `GPIOC->IDR & 0xFF` одним зверненням), PCLK/HREF/VSYNC — окремі піни з EXTI/TIM-захопленням ⟦вибрати вільні піни й
перевірити відсутність конфліктів із таблицею вище за DS10314 та UM1724⟧. Конфлікти з уже використаними лініями: PC13 (кнопка) не в PC0–PC7;
PC0/PC1 винесені на A5/A4 (вільні, АЦП ними не користується). Кадр 160×120 grayscale ≈ 19 КБ — вміщається в RAM (128 КБ).

**Фактично перевірено (2026-10-16):** два серво від 5V Nucleo через USB працюють лише з конденсатором 100 мкФ на живленні серво
і програмним м'яким стартом (виходи PWM вимкнені в спокої, рух по одному, крок 20 мкс / 20 мс); без цього плата скидала USB (журнал: проблема 11).

Висновок: серво **не** живимо від 3V3 (пікові ≈ 1.3 А двох серв ≫ запас LDO; просадка перезавантажила б МК). Від 5 В Nucleo (USB ST-Link, ліміт
≈ 500 мА) також ненадійно при одночасному блокуванні — для рухів під навантаженням потрібне окреме джерело 5 В / ≥ 2 А зі **спільним GND**
(інакше керуючий сигнал PWM не має опорного рівня).

## 4. Параметри шин і розрахунок з дерева тактування

SYSCLK = HSI 16 МГц → PLL (M=16, N=400, P=4) = **100 МГц**; AHB = 100 МГц, **APB1 = 50 МГц** (÷2), APB2 = 100 МГц (`SystemClock_Config`).

| Шина | Налаштування | Розрахунок | Чому |
|------|--------------|-------------|------|
| I2C1 | Standard mode, 100 кГц | CCR = PCLK1 / (2·f) = 50 МГц / (2·100 кГц) = 250 | стандартна швидкість; читання регістрів двома обмінами (без repeated-START), див. проблему 6 |
| SCCB (bit-bang) | 10 мкс на кожну зміну лінії | розрахунок 50 кГц, на записі період 31 мкс ≈ 32 кГц (три зміни ліній на такт, див. `docs/analysis.md`) | SCCB до 400 кГц; 32 кГц із запасом; затримка за DWT-лічильником |
| SPI2 | mode 0 (CPOL=0, CPHA=0), prescaler 128 | 50 МГц / 128 ≈ 390.6 кГц | W25Q підтримує mode 0 і 3 ⟦datasheet⟧; максимум чіпа ≫ 390 кГц, але довгі дроти |
| USART2 | 115200 8N1 | USARTDIV = 50 МГц / (16·115200) = 27.13 → BRR = 27.125; помилка ≈ 0.006 % | VCP ST-Link |
| TIM3 | PWM 50 Гц | f_TIM3 = 2·PCLK1 = 100 МГц; PSC = 99 → 1 МГц (1 тік = 1 мкс); ARR = 19999 → 20 мс = 50 Гц | один таймер для двох серв |
| ADC1 | 12 біт, прескейлер PCLK2/4 | ADCCLK = 100/4 = 25 МГц (≤ 36 МГц), семпл 84 цикли, перетворення (84+12)/25 МГц ≈ 3.84 мкс | високоомне джерело (фоторезистор + 10 кОм) вимагає довгого семплування |
| MCO1 (XCLK) | HSI /1 | 16 МГц (діапазон камери 10–48 МГц) | PLL-джерело давало «сміття» в довіднику |

## 5. Схема підключення (структурна)

```
                         NUCLEO-F411RE
 USB ──── ST-Link ── USART2 (PA2/PA3) ── ПК (лог 115200)
                         │
   3V3 ──────────────────┼── MPU-6050  SCL←PB8(D15)  SDA←PB9(D14)
                         │
   3V3 ── 10к ── SIOC ───┼── OV7670    SIOC←PB10(D6)  SIOD←PB4(D5)  XCLK←PA8(D7)
   3V3 ── 10к ── SIOD    │             PWDN→GND  RESET→3V3
                         │
                         ├── W25Q64    CS←PB12  SCK←PB13  DO→PB14  DI←PB15
                         │
                         ├── GM5528 ×4 (3V3—LDR—ADC—10к—GND): PA0, PA1, PA4, PB0
                         │
 5V (окреме, GND спільний)── SG92R сигнал←PA6(D12)    SG90 сигнал←PA7(D11)
```

## 6. Відхилені варіанти розкладки

1. **SCCB камери на спільній шині I2C1 (PB8/PB9) разом з MPU-6050 через HAL** — відхилено: SCCB не сумісний з I²C у деталях
   (ACK «don't care», немає repeated-START), HAL трактує NACK як помилку й залишає блок у стані BUSY, що «вбиває» і MPU на тій самій шині.
   Bit-bang на окремих PB10/PB4 ізолює збій камери від MPU і працює без прив'язки до апаратного I2C.
2. **SPI1 для флешу (PA5/PA6/PA7)** — відхилено: PA5 = LED LD2 (бортова обв'язка), PA6/PA7 зайняті PWM серво (TIM3). SPI2 на PB13–PB15 вільний.
3. **PWM серво на TIM2_CH1/CH2 (PA0/PA1)** — відхилено: ці піни — канали АЦП квадранта (IN0/IN1).
4. **Камера на апаратному I2C2 (PB10 = SCL) + PB3/PB9 як SDA** — відхилено: SDA I2C2 на PB3 (AF9) = SWO, на PB9 (AF9) конфліктує з I2C1_SDA (PB9 AF4) MPU. ⟦звірити за AF-таблицею DS10314⟧.

## 7. Інструкція зі збирання стенда (для того, хто не монтував)

1. Nucleo відключена від USB. Усі GND з'єднати спільною шиною макетки (до GND Nucleo).
2. MPU-6050: VCC→3V3, GND→GND, SCL→D15, SDA→D14, AD0→GND.
3. OV7670: VCC→3V3, GND→GND, **SIOC→D6, SIOD→D5, XCLK→D7**, PWDN→GND, RESET→3V3; між SIOC–3V3 і SIOD–3V3 по 10 кОм.
4. W25Q64: VCC→3V3, GND→GND, CS→PB12, CLK→PB13, DO→PB14, DI→PB15 (morpho CN10).
5. Фоторезистори: 3V3→GM5528→вузол→10 кОм→GND; вузли → A0, A1, A2, A3.
6. Серво: сигнал → D12 (азимут) і D11 (елевація); живлення 5 В від окремого джерела, його GND — до GND Nucleo.
7. Підключити USB, прошити (`make flash`), відкрити монітор (`make monitor`); очікується `RESULT pass=9 total=9`.
