# PRD — Геліостат з камерою класифікації неба (Heliostat + Sky Classifier)

**Курс:** Системне програмування вбудованих систем
**Платформа:** NUCLEO-F411RE / F446RE (STM32F4, HAL, C)
**Команда:** Андрій Плешу, Тимур Варшавський, група ІО-36
**Версія документа:** 2.0 (ЛР1, проєкт №1 з каталогу методички + розширення по камері)

## A. Загальна ідея

Геліостат — невеликий модуль, який наводить дзеркало (або панель) на джерело світла (сонце),
повертаючи його по двох осях — азимут і елевація. Напрямок на джерело визначається квадрантом
із чотирьох фоторезисторів: порівнюючи освітленість верхньої/нижньої та лівої/правої пар датчиків,
система обчислює, у яку сторону зсунути дзеркало, і відпрацьовує зсув двома серводвигунами.

Камера OV7670 додає другий, незалежний від фоторезисторів канал спостереження за небом:
вона класифікує стан неба (пряме сонце / суцільна хмарність / темрява) за яскравістю,
контрастом і часткою пересвічених пікселів кадру, а також працює «свідком» — зберігає знімок
і запис у журнал, коли освітленість різко падає (підозра на хмару, яка закрила сонце, або
на несправність самих фоторезисторів). Журнал подій і кадри зберігаються в SPI-флеш
(енергонезалежно), керування і калібрування — через UART (CLI).

**Для кого:** навчальний прототип одновісного/двовісного сонячного трекера для подальшого
розвитку (соляні електростанції, невеликі СЕС-трекери, навчальні стенди з робототехніки).
**Чому це має сенс:** просте й дешеве обладнання (4 фоторезистори, 2 хобі-серво) дає робочий
двовісний трекер; камера — незалежна перевірка та доказова фіксація моментів втрати сигналу
("хмара закрила сонце" чи "фоторезистор вийшов з ладу").

ЛР1 не про готовий трекер, а про доведення, що середовище розробки й апаратна база працюють:
Docker-збірка, прошивка, UART-лог, мигання LED, кнопка, ініціалізація I²C/SPI/ADC(×4)/TIM3-PWM
з перевіркою `HAL_OK`, ідентифікація датчиків (self-test). Алгоритми наведення, класифікації
неба та журналювання — завдання ЛР2 і далі.

## B. Обладнання

| Компонент | Інтерфейс | Піни | Навіщо |
|-----------|-----------|------|--------|
| 4× GM5528 (квадрант TL/TR/BL/BR) | ADC (аналог), дільник з 10 кОм | PA0 (IN0, TL), PA1 (IN1, TR), PA4 (IN4, BL), PB0 (IN8, BR) | Визначення напрямку на джерело світла |
| Серво азимуту (SG92R) | PWM 50 Гц | TIM3 CH1 / PA6 | Поворот по горизонталі |
| Серво елевації (SG90) | PWM 50 Гц | TIM3 CH2 / PA7 | Поворот по вертикалі |
| W25Q64 | SPI2 | PB13/14/15, CS PB12 | Журнал подій, конфігурація калібрування, кільцевий буфер кадрів |
| OV7670 | SCCB (I²C1) + паралельна шина + XCLK | PB8/PB9 (SCCB), PA8 (XCLK) | Класифікація стану неба за кадром, «свідок» втрати сигналу |
| MPU-6050 (опційно) | I²C1 | PB8/PB9 | Зворотний зв'язок по нахилу платформи (перевірка, що дзеркало дійсно повернулось) |
| LED LD2, кнопка B1 | GPIO | PA5, PC13 | Індикація режиму, ручне керування/скидання |
| USART2 (ST-Link VCP) | UART | PA2/PA3 | Діагностичний лог і CLI калібрування, 115200 8N1 |

Серво живляться від **5V** плати (не від 3V3!), спільний GND з платою. Усі інші модулі — 3.3 В.
Докладний розподіл пінів і схема дільників — `docs/hardware-components.md`.

## C. Функціональні вимоги

| ID | Вимога |
|----|--------|
| FR-01 | Система повинна опитувати всі 4 канали АЦП квадранта (TL, TR, BL, BR) з частотою не менше 100 Гц. |
| FR-02 | Система повинна обчислювати зсув по осі азимуту як різницю (TL+BL) − (TR+BR), і по осі елевації як (TL+TR) − (BL+BR). |
| FR-03 | У режимі TRACK система повинна наводити серво азимуту й елевації так, щоб мінімізувати обчислений зсув (пряме сонце, активне стеження). |
| FR-04 | Кут кожного серво повинен обмежуватись каліброваними межами імпульсу (окремо для SG92R і SG90), не допускаючи виходу за межі без заклинювання рога. |
| FR-05 | Якщо сумарна освітленість (TL+TR+BL+BR) нижче порога темряви довше заданого часу, система повинна перейти в режим PARK: зафіксувати серво в безпечному положенні й зупинити наведення. |
| FR-06 | Якщо освітленість середня, але контраст між квадрантами низький (розсіяне світло), система повинна перейти в режим OVERCAST: серво не рухаються, опитування датчиків відбувається рідше. |
| FR-07 | Система повинна вести журнал подій у W25Q64 записами фіксованого формату (тип події, відносна мітка часу в мс, значення датчиків/зсуву). |
| FR-08 | Журнал повинен зберігатися після вимкнення живлення і зчитуватись після перезапуску без втрат. |
| FR-09 | Система повинна підтримувати CLI-команди калібрування через UART: встановлення мін./макс. імпульсу окремо для серво азимуту (SG92R) і елевації (SG90), читання поточної калібровки. |
| FR-10 | Система повинна індикувати поточний режим (TRACK / OVERCAST / PARK) світлодіодами. |
| FR-11 | Система повинна робити знімок камерою OV7670 (grayscale, програмне захоплення без DCMI, 160×120) не частіше ніж 1 раз на 3 с; автоекспозиція камери вимкнена, підсилення зафіксоване. |
| FR-12 | Система повинна класифікувати стан неба за кадром (середня яскравість, контраст, частка пересвічених пікселів) на CLEAR / OVERCAST / DARK не рідше ніж 1 раз на 10 с. |
| FR-13 | У стані класифікації OVERCAST серво не повинні рухатись, незалежно від зсуву, обчисленого за квадрантом (FR-02/03 призупиняються). |
| FR-14 | Якщо сума чотирьох каналів АЦП падає більш ніж на 50 % за 2 с, або система входить у PARK, повинен зберігатися знімок у W25Q64 і записуватись подія «втрата сигналу» в журнал. |
| FR-15 | Збережені кадри повинні зберігатися в кільцевому буфері останніх 20 кадрів (перезапис найстаріших); запис журналу повинен містити посилання на номер збереженого кадру. |
| FR-16 | Система повинна виявляти розбіжність між яскравістю кадру камери і сумою фоторезисторів (понад поріг) і записувати подію «підозра на несправність датчика». |
| FR-17 | Система повинна (опційно) зчитувати кут нахилу з MPU-6050 як додаткову перевірку того, що механічне положення відповідає команді серво. |
| FR-18 | Система повинна виводити діагностичний лог через UART на швидкості 115200 8N1. |

## D. Альтернативи, які розглядались

| Компонент | Альтернатива | Чому відхилена |
|-----------|--------------|-----------------|
| 4× GM5528 (квадрант) | BH1750 (I²C, люкс) ×4 через мультиплексор | Потрібен I²C-мультиплексор (адреса фіксована), ускладнює шину; ADC-дільник простіший і є вимогою курсу. |
| 4× GM5528 (квадрант) | Один квадрантний фотодіод (PSD) | Потребує аналогового підсилювача й більш складної обв'язки, немає в комплекті курсу. |
| Серво SG92R/SG90 | Крокові двигуни + драйвер (A4988/DRV8825) | Надлишкова точність для цієї задачі, додатковий драйвер і живлення, складніше калібрування. |
| OV7670 (класифікація неба) | BH1750 (один датчик освітленості) | Простіший, але дає лише одне число (люкс), не бачить контрасту/пересвічення і не може зробити знімок-доказ. Обрано як резервний варіант, якщо камера вийде з ладу. |
| OV7670 (класифікація неба) | Додатковий окремий фоторезистор, спрямований у зеніт | Грубий індикатор загальної освітленості неба без картинки; не дає діагностики розбіжності з квадрантом. |
| W25Q64 (SPI) | Зовнішня EEPROM 24LC256 | Замала ємність для кільцевого буфера кадрів 160×120. |
| W25Q64 (SPI) | microSD + файлова система | Більше коду, вищий струм, складніша обробка помилок — не виправдано для цього обсягу даних. |
| MPU-6050 (зворотний зв'язок) | Потенціометр на осі серво | Потребує механічної доробки осі; MPU-6050 вже є в комплекті курсу і досить для грубої перевірки. |

Покриття інтерфейсів: **ADC** (квадрант GM5528), **PWM/таймер** (TIM3, серво), **SPI** (W25Q64),
**I²C** (OV7670 SCCB, MPU-6050), **UART** (лог і CLI), **GPIO** (LED, кнопка). Мінімум трьох
різних інтерфейсів дотримано.

### Статус після ЛР1
За методичкою курсу ЛР1 вимагає лише bring-up і UART-логер (підтверджено викладачем:
ідентифікація й налагодження датчиків — це ЛР2). Цю мінімальну вимогу виконано й перевірено
багаторазово: банер, `SYSCLK = 100000000 Hz`, ініціалізація USART2/I2C1/SPI2/ADC1 (4 канали
квадранта)/TIM3 (PWM 50 Гц bring-up для серво, без алгоритму наведення) — усі `HAL_OK`; LED
блимає, кнопка B1 опрацьовується, `tick` друкується щосекунди.

Понад мінімум ми також підключили реальні датчики і чесно задокументували результат
(повний журнал — `docs/problems.md`):
* **Квадрант фоторезисторів GM5528** (4 канали ADC) — стабільно PASS у кожному тесті сесії.
* **MPU-6050** та **W25Q64** (чіп виявився W25Q64JV-IQ, не W25Q32 — виправлено) —
  обидва неодноразово підтверджено справними (`WHO_AM_I=0x68`, `JEDEC=EF 40 17`), але
  з'єднання на макетній платі виявились електрично нестабільними: результат чергувався
  між PASS/FAIL без зміни проводів. Знайдено й виправлено реальні помилки монтажу (переплутані
  VCC/GND, потім SCL/SDA на MPU-6050), знижено швидкість I2C1/SPI2 для стійкості — це істотно
  покращило, але не усунуло повністю нестабільність контактів.
* **OV7670** — жодного разу не відповів на SCCB за сесію; за вказівкою викладача перевірку
  камери залишено останньою і відкладено на ЛР2.
* **Серво** (SG92R/SG90) — PWM-bring-up ініціалізований (`HAL_OK`), але фізичного руху/реакції
  при подачі живлення не зафіксовано; причина (ймовірно, живлення 5V) не перевірена
  мультиметром.

FR-01–FR-17 (наведення, класифікація, журналювання, калібрування) реалізуються в ЛР2–ЛР6;
стабілізація монтажу (нові jumper-дроти та/або інша макетна плата) — перший крок ЛР2.
